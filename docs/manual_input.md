# 人工輸入流程操作說明（PRD 2.5）

104 自 2026-11-24 起阻擋程式存取。在這段期間，改由維護者本人在 104 網站找職缺，系統只分析貼上的內容，**完全不連線 104**。

## 第一次設定（只做一次）
1. 確認 `C:\dev\pm-pjm-jobs` 已有 `.venv`（Python 虛擬環境）與 `.env`（Gemini 金鑰，使用本機專用金鑰，不用 GitHub 上的正式金鑰）。
2. 確認已用 `gh auth login` 登入 GitHub（推送資料與啟動部署需要）。
3. 在 PowerShell 執行一次：
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File C:\dev\pm-pjm-jobs\tools\make-shortcuts.ps1
   ```
   桌面會出現「更新職缺」與「職缺收件匣」兩個捷徑。

## 每天的步驟（約 15 分鐘）
1. **在 104 找職缺**（設定一次後存成書籤）：
   * 職務類別：產品經理、產品管理師、產品企劃、專案經理、軟體專案管理師、其他專案管理師。
   * 工作經歷：1 年以下、1–3 年；工作性質：全職；排序：最新刊登。
   * 往下看到**上次收錄日（含）以前**的日期就停。第一次從 2026-11-24 開始補。
   * 不必判斷是不是上市櫃公司或職稱是否符合，系統會過濾。
   * 省時小技巧：每天可點 104 的「**本日最新**」只看今天的職缺；職缺卡片上有「**上市上櫃**」標籤的優先收。沒有標籤的也可以收，因為興櫃公司與上市櫃公司的子公司不一定有這個標籤，系統會再比對。
2. **貼進收件匣**：打開職缺頁 → `Ctrl+A`、`Ctrl+C` → 在「職缺收件匣」新增一個 `.txt`：
   * 第一行：職缺網址（例：`https://www.104.com.tw/job/abc12`）
   * 第二行起：`Ctrl+V` 貼上整頁內容 → 存檔（UTF-8）。
3. **點兩下「更新職缺」**，等它跑完，看結果摘要：
   * ✅ 新增：已上架到網站。
   * ⏭️ 略過：職稱不符、年資超過 3 年、或非上市櫃公司（檔案已刪除）。
   * 🔁 已收錄過：只更新刊登日。
   * ⚠️ 無法處理：檔案移到 `inbox\failed`，依說明修正後放回收件匣，或直接刪除。
   * ⏸️ Gemini 額度用完或忙碌：檔案留在收件匣，之後再執行即可。
4. 2–3 分鐘後打開網站確認。

## 注意
* 收件匣與 `data` 資料夾都不會提交到 repo 的程式分支；貼上的頁面文字處理後即刪除，不保存。
* 這段期間不做職缺下架判定，網站會顯示「下架狀態停在 2026-11-23」的說明。
* 每日自動排程仍會嘗試一般連線；若 104 恢復允許程式存取，系統會自動回到完整爬取，屆時停止人工流程。
